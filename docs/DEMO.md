# Demo: Acme Outdoor

`./lakehouse demo` (also part of `quickstart`) builds a small, fully synthetic web shop in the Iceberg schema `shop`. The raw
tables are generated by plain Trino SQL, the marts by **dbt**, and a stream of order events flows through **Kafka and Flink**.
Nothing is downloaded, and the data is rebuilt identically each time relative to today's date, so charts always look current.
Running it again replaces the tables; Superset objects are updated in place.

## Data model

| Table | Rows | Columns (selection) |
| --- | --- | --- |
| `customers` | 5,000 | `customer_id`, `signup_date`, `country`, `acquisition_channel`, `marketing_opt_in` |
| `products` | 48 | `product_id`, `product_name`, `category`, `unit_price` |
| `orders` | 30,000 | `order_id`, `customer_id`, `order_date`, `product_id`, `quantity`, `discount_pct`, `amount`, `status` |
| `orders_enriched` | 30,000 | orders joined with customer and product attributes (dbt, intermediate) |
| `daily_revenue` | ~13,700 | day x country x category: `orders`, `units`, `gross_revenue`, `refunded_revenue`, `net_revenue` |
| `customer_value` | 5,000 | per customer: `orders`, `net_revenue`, `value_tier`, `lifecycle_status` |
| `monthly_cohorts` | ~190 | signup cohort x months since signup: `cohort_size`, `active_customers`, `retention` |
| `order_events` | 600 after the demo | streamed by Flink from Kafka: `event_id`, `order_id`, `amount`, `status`, `event_time`, `ingested_at`, `kafka_offset` |
| `live_orders_by_hour` | ~20 | hourly rollup of `order_events` (dbt, streaming) |

The first three are raw (`demo/sql/01_seed.sql`), the marts are dbt models in `dbt/models/`, and `order_events` is written by the Flink
job in `flink/sql/orders_stream.sql`. Amounts are in EUR.

## Query it

```sh
./lakehouse sql
```

```sql
-- revenue and refund rate by category
SELECT category, round(sum(net_revenue)) AS revenue,
       round(100 * sum(refunded_revenue) / sum(gross_revenue), 1) AS refund_pct
FROM shop.daily_revenue GROUP BY 1 ORDER BY 2 DESC;

-- which acquisition channel brings the most valuable customers?
SELECT acquisition_channel, count(*) AS customers, round(avg(net_revenue), 2) AS avg_ltv
FROM shop.customer_value GROUP BY 1 ORDER BY 3 DESC;

-- Iceberg features: time travel and table metadata
SELECT * FROM shop."orders$snapshots";
SELECT count(*) FROM shop.orders FOR VERSION AS OF <snapshot_id>;
```

Also available: `--format csv|json`, `-f file.sql`, or pipe SQL on stdin.

## Dashboard

`./lakehouse open dashboard` opens **Acme Outdoor - sales overview**: four KPIs, revenue by month, revenue by category,
revenue by country, customers by value tier and lifecycle, acquisition channel economics and a cohort retention heatmap.
Every chart is an ordinary Superset chart on a dataset with saved metrics (`net_revenue`, `aov`, `refund_rate`, `customers`,
`avg_ltv`, ...), so you can click **Edit chart**, change the metric or grouping and **Save as** a new chart. Four saved
queries in SQL Lab show window functions, joins and an activation list. Seeded objects are matched by name and overwritten
when you rerun the demo, so use **Save as** before customising.

The second dashboard, **AQUIFER - streaming pipeline (Kafka, Flink, Iceberg)**, reads `shop.order_events` directly: totals, events
over time, events by status and the latest events with their Kafka partition and offset. Run `./lakehouse stream --events 300
--rate 30` and refresh it after about 20 seconds.

## Orchestrate it

The Airflow DAG `shop_marts` (daily, paused by default) runs `dbt build` on the shop project: models and tests. Open Airflow
(`./lakehouse open airflow`), unpause it and trigger a run. Because the DAG runs the same dbt project as `./lakehouse dbt build`,
edit a model in `dbt/models/`, trigger the DAG and refresh the dashboard to see a change flow end to end.
`shop_streaming_marts` (hourly) builds the streaming mart. `iceberg_smoke` is a minimal Airflow to Trino to Iceberg to MinIO round
trip, also exercised by `./lakehouse smoke` and `./lakehouse check`.

## Build on it

- Add DAGs: drop a `.py` file in `airflow/dags/`; the DAG processor lists the folder every few minutes by default, so a new
  file can take up to about five minutes to appear (the folder is mounted read-only inside the container).
- Add SQL: new files under `demo/sql/` can be run with `./lakehouse sql -f demo/sql/yourfile.sql`.
- Add data: `./lakehouse load demo/data/support_tickets.csv` (CSV, TSV or JSON lines; types are inferred; table
  `data.support_tickets`; `--table schema.name` and `--replace` are available), or
  `CREATE TABLE iceberg.myschema.t WITH (format = 'PARQUET') AS SELECT ...`; then in Superset use
  **Datasets > + Dataset** on the *Lakehouse (Trino, general)* connection.
- Explore in Python: `./lakehouse up --with notebook`, then `./lakehouse open notebook` (JupyterLab with `query()`, `duck()` and
  `catalog()` helpers and a welcome notebook in `notebooks/`).
- Keep a copy: `./lakehouse backup` writes all data to `backups/`; `./lakehouse restore FILE` brings it back.
- Stream: Redpanda Console shows topics and schemas; produce with any Kafka client to `localhost:19092` (the printed Kafka port).
- Look inside: MinIO console shows the Parquet and metadata files under the `warehouse` bucket.

## Remove it

```sql
DROP TABLE iceberg.shop.orders; -- and the other five, then:
DROP SCHEMA iceberg.shop;
```

or `./lakehouse reset` to start from nothing.
